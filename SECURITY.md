# Security reporting

Security fixes are maintained on the main development branch. A formal support schedule for older releases has not been established.

Use the repository's private vulnerability reporting facility when available. If it is unavailable, contact the maintainer through the contact information on their GitHub profile before disclosing sensitive technical details publicly.

A useful report includes the affected application version, relevant Android and server versions, reproduction steps, expected impact, and a minimal example using test data. Do not include real passwords, app passwords, personal tasks, or private server addresses.

Areas of particular interest include credential handling, CalDAV origin validation, XML parsing, imported task data, Android component exposure, and unintended data deletion.
